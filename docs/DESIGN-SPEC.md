# مواصفة الهوية البصرية — البورتفوليو

> وثيقة مرجعية. اقرأها كاملة قبل أي تعديل. كل قرار هنا له سبب مذكور — إذا اضطررت تخالف قرارًا، اذكر ليش.

---

## 0. القاعدة الحاكمة

الموقع له **أطروحة واحدة**:

> الخطأ ليس فشلًا. الخطأ هو آلية التعلم نفسها.

سبب وجودها: المالك يشتغل على أربعة مجالات تبدو منفصلة — ذكاء اصطناعي، روبوتات، هندسة برمجيات، السلوك البشري — وكلها تشترك في حلقة واحدة: جرّب، اقس الانحراف، عدّل، كرّر. الإنسان يتعلم المشي كذا، والشبكة العصبية تتدرب كذا، والمبرمج يبني كذا.

كل قرار بصري في هذي الوثيقة يخدم هذي الجملة. **أي إضافة لا تخدمها = تُرفض**، حتى لو كانت جميلة.

الموقف الضمني: كل بورتفوليو يعرض النتائج المصقولة ويخفي المحاولات. هذا الموقع يعرض المحاولات.

## 1. الحدود التقنية (لا تُخالَف)

## 2. المادة اللونية

مادتان فقط: **حبر** و**ذهب**. لا لون ثالث. لا أحمر، لا أخضر، لا أزرق — ولا حتى للحالات.

الوضعان انعكاس لبعض: الفاتح = ورق دافئ والرسم بالحبر (منطقة الإنسان). الداكن = حقل حبري والرسم بالذهب (منطقة الآلة). التبديل بينهما يمشي رحلة الموقع نفسها.

### قاعدة حرجة

**الصبغة ثابتة، القيمة تنقلب.** الذهب الفاتح `#d9ad48` على ورق يعطي تباينًا ~٣:١ ويسقط في الوصولية. فله قيمتان مختلفتان حسب الوضع. استخدام نفس الهيكس في الوضعين خطأ يفسد الوضع الفاتح بالكامل.

### بلوك الـ tokens

يُوضع في الملف العام. الوضع الداكن هو الافتراضي.

```css
:root {
  /* الحبر — الأرضية في الوضع الداكن */
  --ink-900: #090c0b;
  --ink-800: #111614;
  --ink-700: #1a211e;

  /* الورق — الأرضية في الوضع الفاتح */
  --paper-100: #f4f0e6;
  --paper-200: #ebe5d7;
  --paper-300: #ded7c5;

  /* الذهب — قيمتان لنفس الصبغة */
  --gold-light: #d9ad48;   /* يُستخدم على الحبر */
  --gold-dark:  #6b5312;   /* يُستخدم على الورق */

  /* المسافات — شبكة 8pt */
  --space-1: 0.25rem; --space-2: 0.5rem;  --space-3: 0.75rem;
  --space-4: 1rem;    --space-6: 1.5rem;  --space-8: 2rem;
  --space-12: 3rem;   --space-16: 4rem;   --space-24: 6rem;

  /* القياس النصي */
  --text-sm: 0.875rem; --text-base: 1rem;  --text-lg: 1.125rem;
  --text-xl: 1.5rem;   --text-2xl: 2rem;
  --text-hero: clamp(2.25rem, 6vw, 4rem);

  --radius-sm: 0.5rem; --radius-lg: 1rem; --radius-full: 9999px;

  /* الحركة — انظر القسم 4 */
  --ease-settle: cubic-bezier(0.22, 1.08, 0.36, 1);
  --ease-linear-out: cubic-bezier(0.4, 0, 0.2, 1);
  --dur-fast: 140ms;
  --dur-base: 320ms;
  --dur-heavy: 520ms;
}

/* الوضع الداكن — الافتراضي */
:root, [data-mode="dark"] {
  --bg: var(--ink-900);
  --surface: var(--ink-800);
  --text: #ece5d5;
  --text-muted: #9a9384;
  --text-dim: #625d52;
  --mark: var(--gold-light);
  --border: rgba(236, 229, 213, 0.10);
  --border-strong: rgba(236, 229, 213, 0.20);
  --trace: rgba(217, 173, 72, 0.05);
}

[data-mode="light"] {
  --bg: var(--paper-100);
  --surface: var(--paper-200);
  --text: #171310;
  --text-muted: #5a5449;
  --text-dim: #8a8377;
  --mark: var(--gold-dark);
  --border: rgba(23, 19, 16, 0.12);
  --border-strong: rgba(23, 19, 16, 0.24);
  --trace: rgba(23, 19, 16, 0.05);
}
```

### قواعد الاستخدام

- `--mark` (الذهب) يُستخدم **حصريًا على المسار المُصحَّح** — النتيجة الناجحة، الرقم المحوري، الحالة النشطة. ندرته هي قيمته. إذا ظهر في أكثر من ٣–٤ مواضع في الشاشة الواحدة، فقد معناه.
- صفر هيكس خام في المكوّنات. `var(--...)` دائمًا.
- التبديل بين الوضعين يكون بـ `data-mode` على `<html>`، مع احترام `prefers-color-scheme` كافتراضي أول، وحفظ اختيار المستخدم في `localStorage`.
- انتقال التبديل: `--dur-base` على `background-color` و`color` فقط. لا تُحرَّك بقية الخصائص وقت التبديل.

## 3. ترميز الخطأ — بدون لون

بما إن اللون محذوف كأداة ترميز، الخطأ يُرمَّز بـ**السلوك**. هذا أصدق للأطروحة وأقل حاجة لشرح.

| الحالة | الترميز البصري |
| --- | --- |
| تردد / انحراف | خشونة: مسار مكسور، خط مهتز، حواف غير مستقرة |
| تصحيح / نجاح | نظافة: خط واحد مستقر + وسم ذهبي |
| محاولة فاشلة | خفوت: تبقى كأثر بكثافة `--trace` (٥٪ كحد أقصى) ولا تُمسح أبدًا |
| قبل الاستقرار | إزاحة: العنصر يظهر مزاحًا ثم ينضبط |

**الوضوح هو المكافأة.** المسار الناجح هو الوحيد المقروء تمامًا؛ كل ما عداه أثر باهت.

## 4. الحركة — تخميد ناقص

أهم تفصيل في الموقع كله، وأكثر واحد يفرّق.

المفاصل الحقيقية — عضلة أو ذراع آلية — **تتجاوز الهدف بقليل ثم ترجع**. `ease-out` القياسي يوقف الشيء بنعومة تامة، وهذا إحساس برمجي لا فيزيائي.

- استخدم `--ease-settle` كافتراضي. التجاوز فيه ~٢–٣٪ فقط.
- **ليس ارتدادًا مرحًا.** أي منحنى فيه تجاوز يتعدى ٥٪ يقرأ كلعبة أطفال ويقتل جدية الموقع. `cubic-bezier(0.34, 1.56, ...)` مرفوض.
- **الوزن له فيزياء:** العنصر الثقيل (بطاقة مشروع، قسم) يستقر بـ `--dur-heavy`. الخفيف (وسم، أيقونة، مؤشر) بـ `--dur-fast`. لا توحّد المدد.
- حرّك `transform` و`opacity` فقط. أي حركة على `width` أو `height` أو `top` أو `margin` مرفوضة — تسبب تململ التخطيط وتحس بطيئة على أندرويد متوسط.
- التتابع عند دخول عدة عناصر: ٦٠–٩٠ms بين كل واحد.

**سبب هذي القاعدة:** الروبوتات مجال ينوي المالك دخوله ولم يدخله بعد. فهي لا تُعرض كادعاء خبرة، بل **كلغة حركة**. الزائر ما يقرأ كلمة "روبوتات" لكنه يحس تحت يده بكتلة وقصور ذاتي.

## 5. تسلسل التعاير عند الفتح

يشتغل مرة واحدة لكل جلسة، مدته ~٢.٥ ثانية.

| اللحظة | ما يحدث |
| --- | --- |
| 0ms | النص كامل ومقروء. لكن المحاذاة مزاحة ~6px، المسافات بين العناصر غير متساوية، إيقاع الظهور مرتبك قليلًا. مؤشر مونوسبيس صغير في زاوية: `calibrating` |
| 0–2200ms | كل شي يعاير نفسه تدريجيًا: المحاذاة تنضبط، المسافات تتساوى، الارتجاف يخفت |
| 2200ms | المؤشر يتحول إلى `stable` ثم يخفت بعد ثانية |

**المؤشر هو صمام الأمان.** بدونه الزائر يقرأ الإزاحة كعطل تقني ويغادر. معه تصير إعلان نية.

قواعد إلزامية:
- النص **مقروء من الإطار الأول**. الحركة تحصل حول النص لا بدلًا منه. صفر حجب للمحتوى.
- مرة واحدة فقط لكل جلسة عبر `sessionStorage`. التكرار مع كل تنقّل يحوّلها لتهريج.
- تُلغى بالكامل مع `prefers-reduced-motion` — تُعرض الحالة النهائية مباشرة، بلا مؤشر.
- لا تؤثر على `Largest Contentful Paint`. لا تستخدم `opacity: 0` كنقطة بداية للنص.

## 6. الخلفية — الأثر المتبقي

طبقة `<canvas>` واحدة خلف المحتوى، بمكوّن مستقل يقبل props.

### المنطق

بنية متفرّعة تُرسم ببطء. من بعيد تُقرأ كجهاز عصبي، وعن قرب تلقى فيها زوايا ٤٥ درجة و`vias` ونقاط لحام — **بلا حد فاصل بين العصب والدائرة**. هذا الالتباس مقصود: المالك يفهم الإنسان ليبني آلة أحسن.

كل مسار يُرسم بالمنطق نفسه: يحاول يوصل هدفه، يتجاوزه، يرجع، يستقر. **المسارات الفاشلة تبقى** كأثر بكثافة `--trace`. المسار الأخير الناجح وحده ياخذ `--mark`.

النتيجة: كثافة اللوحة = خريطة الصعوبة. كثيفة حيث كثر التردد، نظيفة حيث كان القرار سهلًا.

### التدرّج عبر الصفحة

الخلفية تتغيّر حسب موضع السكرول:

| المنطقة | الشكل |
| --- | --- |
| الأعلى | عضوي بالكامل: خطوط مرتجفة، تفرّع غير منتظم، لا شبكة ولا محاذاة |
| الوسط | تحوّل: الزوايا تقترب من ٤٥ درجة، المسافات تتساوى تدريجيًا، الارتجاف يقل |
| الأسفل | هندسة صارمة: شبكة نظيفة، مسارات مستقيمة، `vias`، صفر عشوائية |

الزائر ينزل فيتحوّل تحت يده من ملاحظة إنسانية إلى منتج هندسي. هذي الجملة التي لا تُكتب.

### قيود الأداء (إلزامية)

- توقّف الرسم بـ `IntersectionObserver` عند خروج الكانفس، وبـ `visibilitychange` عند إخفاء التبويب.
- على عرض < 700px: نصف عدد المسارات، وسمك أثر أقل.
- سقف `devicePixelRatio` عند 2.
- عند `prefers-reduced-motion`: **إطار واحد ساكن** يُرسم مرة ثم يتوقف الحلقة نهائيًا. اللوحة الساكنة لازم تكون معبّرة بذاتها — الأثر والمسار المصحح موجودان، فقط بدون حركة.

## 7. عرض المشاريع

### المبدأ

القليل القوي. **صفر حقول قابلة للتوسيع** — لا accordion، لا "اقرأ المزيد"، لا درج. زر "المزيد" اعتراف بالعجز عن الاختيار.

العمق موجود، لكن في **صفحة مشروع مستقلة** بمسار خاص، لا في درج داخل البطاقة. التقني الذي يبي يتعمق يضغط ويدخل صفحة كاملة؛ غير التقني يفهم كل شي من البطاقة ولا يشعر أنه فاته شي.

### بنية البطاقة

أربعة عناصر بالضبط، بهذا الترتيب:

```
[اسم المشروع]
[رقم واحد]              ← بالمونوسبيس، بلون --mark
[ملخص: جملة أو جملتان]  ← وش هو فعلاً
[سطر ما انكسر]          ← بلون --text-dim
→ [رابط لصفحة المشروع]
```

**الملخص** هو أهم نص في الموقع. شروطه:
- يشرح **وش يسوي المشروع فعلًا** لا التقنيات المستخدمة فيه
- يفهمه غير التقني بالكامل، ويحترم عقل التقني في نفس الوقت
- بلاغة عالية، صفر حشو، صفر كلمات تسويقية (`قوي`، `متطور`، `مبتكر`، `سلس` كلها ممنوعة)
- المعيار: لو حذفت أي كلمة، هل تنقص المعنى؟ إذا لا، احذفها

**الرقم الواحد** يكون **الأصعب أو الأغرب، لا الأكبر**. الأرقام الكبيرة تُقرأ كتباهٍ؛ الرقم الصعب يُقرأ كثقة.

**سطر ما انكسر** يذكر ما لم ينجح وما تعلّمه المالك منه. هذا السطر أثمن من كل المقاييس، لأن كل بورتفوليو يقول "دقة ٩٧٪" وواحد فقط يقول أين انكسر.

**ممنوع في البطاقة:** وسوم تقنية (`React` `Python` `PyTorch`)، شعارات، أيقونات تقنيات، شريط مهارات، نسب مئوية للإتقان.

### عدد المشاريع

**ثلاثة فقط** على الصفحة الرئيسية. المشروع الرابع يسحب انتباهًا من الثلاثة الأوائل أكثر مما يضيف. الباقي في صفحة أرشيف منفصلة إن لزم.

### صفحة المشروع المستقلة

هنا يذهب كل ما حُذف من البطاقة: المعمارية، القرارات التقنية وأسبابها، المقاييس الكاملة، الحدود والقيود، ما جُرّب وفشل، الكود إن كان مفتوحًا. بنفس المبدأ: نص محرَّر لا مكدّس.

## 8. الاستجابة و RTL

- **موبايل أولًا.** كل استعلامات الوسائط بـ `min-width`. اختبر ذهنيًا عند 320px و768px و1280px.
- لا عرض ثابت بالبكسل على أي حاوية. `clamp()` و`%` و`min()`.
- شبكة البطاقات: `grid-template-columns: repeat(auto-fit, minmax(min(300px, 100%), 1fr))`.
- خصائص منطقية إلزامية: `margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `text-align: start`. لا `left`/`right` مطلقًا.
- الأرقام والمصطلحات الإنجليزية داخل نص عربي: غلّفها بـ `dir="ltr"` حتى لا ينقلب ترتيبها.
- على الموبايل: الخلفية تبقى فعّالة لكن بكثافة أقل. لا تستبدلها بصورة ساكنة إلا عند `prefers-reduced-motion`.

## 9. الوصولية

- تباين ٤.٥:١ للنص العادي و٣:١ للعناوين الكبيرة — **في الوضعين**. اختبر الوضع الفاتح تحديدًا، فهو الذي يسقط عادة.
- حلقة تركيز مرئية على كل عنصر تفاعلي، تستخدم `--mark`.
- كل شي يُوصل بالـ Tab. رابط تخطٍّ للمحتوى.
- `aria-label` على الأزرار الأيقونية. `aria-hidden="true"` على الكانفس بالكامل.
- مفتاح النجاة العام:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

**اختبار قبول:** أطفئ الحركة تمامًا، والوضعين معًا. هل الأطروحة (الخطأ آلية تعلم) لا تزال مقروءة من الطبقة الساكنة — من اللوحة الساكنة ومن سطر "ما انكسر" في كل بطاقة؟ إذا لا، فالفكرة معلّقة على الحركة وحدها وهذا فشل.

## 11. متروك للمالك — اسأل، لا تخمّن

هذي قرارات لم تُحسم بعد. **لا تخترع لها قيمًا**. نفّذ بمحتوى مؤقت واضح ثم اسأل:

1. **الخطوط** — العربي والمونوسبيس، وأيهما يحمل الطابع
2. **سطر الهيرو** — الجملة التي تلخّص المالك
3. **المشاريع الثلاثة** وأي منها يتصدر
4. **الرقم الواحد** لكل مشروع، وملخصه، وسطر ما انكسر
5. **سطر النية بخصوص الروبوتات** — إن وُجد

---

## 12. سير العمل

1. اشتغل على برانش منفصل. لا تدفع على `main`.
2. اقرأ قبل ما تكتب. لا تعدّل ملفًا ما شفته.
3. طابق الأنماط الموجودة في الريبو — أسماء الـ tokens، بنية الملفات، شكل الـ props.
4. كوميتات صغيرة موصوفة. كل كوميت يخص شيئًا واحدًا.
5. `npm run lint` و`npm run build` ينجحان قبل أي إعلان بالانتهاء.
6. عند كل تسليم: اذكر ما تغيّر، وليش، وما بقي.
